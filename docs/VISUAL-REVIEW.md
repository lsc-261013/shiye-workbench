### 发现后修正

1. 手机保存区使用bottom sticky时，在字段尚未进入视口前就浮到上方，覆盖阅读顺序；改为正常文档流，实看375笔记和390×500短视口，取消、保存与更多可触达。
2. 1280笔记区下方操作需要更多滚动；收紧顶栏/工具纵向间距和短桌面笔记间距，保留字体大小，画板提高到约53%，操作可滚到。
3. 未提交笔记时阻止拖动后，浏览器仍可能选中图片/文字；阻止默认桌面指针行为并禁止画板卡片原生文字选区。正常拖动和缩放重新实测，分别撤销恢复。
4. 看图和编辑入口不再共用弹窗；新链接的关闭/Esc/取消对已填写内容做同弹窗放弃确认，不叠另一个编辑查看层。
5. 超过12个元素先拒绝整理，再考虑图片解码，避免大素材方案为一个不能执行的整理动作产生等待。13元素再次实际操作，原备份保持一致。

- 桌面采用素材、画板、当前详情三个区域。详情大图和完整笔记解决选中对象不易读的问题，缩略图红框与画板红框建立对应；层级、替换和移除在详情集中出现。比首版占用更多侧边宽度，画板按可用宽高缩放，1440及1280均完整可见，导出坐标保持不变。可收起素材栏扩展画板。

### 本轮实际发现和修正

1. 自动操作下方案名失焦没有提交：兼顾`change`与`blur`，并在App按完整内容去重，避免重复历史。复查标题及刷新恢复通过。

3. 844×390横屏原先进入桌面布局、有缩放手柄：扩展轻编辑媒体条件，按可用高度限制整板显示。复查完整1600×1000全貌、0手柄、无横向溢出。

5. 浏览器连续切尺寸时部分截图捕获过早：核对实际CSS视口与图像宽高，稳定后补拍；原版用起点源码快照独立运行。属于证据采集问题，不把它写成产品布局bug。

## 实际发现与修正

1. **叠放遮住缩放手柄**：手柄改成画板末尾独立覆盖层，素材本身层叠不变。实际拖动后从 720×475 变为 817.762×539.496，比例保持；撤销恢复。
2. **笔记本底部画板超出首屏**：按可用宽度和高度共同计算显示缩放。在 1366×768 下画板边界为 x≈382.8、y≈136.0、宽≈846.4、高529，完整落在视口内；不改变导出坐标。
3. **侧栏拖入反馈不足**：采用指针捕获与跟随提示，越过起拖阈值后显示“松手加入画板”。实际从侧栏拖入产生第六个元素，落点 x≈694.1 / y≈669.1，没有误打开详情。
4. **手机工具位置**：把选中工具改为底部面板，保留顶部保存、撤销和导出。手机没有显示缩放手柄。
5. **最小缩放浮点边界**：最小高度计算可能得到 99.99999999999999，导致合法备份被拒；在坐标工具约束最小值，相关测试通过。

## 动效与操作证据

以直接反馈为主，只有轻量控件颜色过渡，没有滚动劫持、循环动画或入场等待。实际进行了连续拖动、稳定松手、一次撤销、预览退出、详情关闭返回原素材和手机点选。详情通过原生 dialog 保留焦点并在关闭后回到打开控件。

提供 `prefers-reduced-motion` 规则。本机验收工具应用了与该规则相同的无动画 / 无过渡覆盖样式后完成预览、返回与导出；未修改用户操作系统设置，不将此称作真实系统偏好或手机真机验证。

视觉材料调整属于 v2 允许的普通细节。未改为暗色、渐变发光风格，也未引入概念图外的编辑功能。
