# 第二轮三分钟演示与事实清单

当前交接见 `HANDOFF-ROUND-TWO-2026-10-06.md`，验收范围见 `VERIFICATION.md`。下列用户练习尚未实际完成，不记录为已掌握。

## 操作顺序

1. 打开4186，继续草稿；使用新空白方案前先导出JSON，切换需确认。
2. 上传两张横竖图片，指出已放入的数量和暂留素材的反馈。选择图片，点「看大图」直接查看，再关闭。
3. 就地写下一条想法，点击保存修改。再改一行并切换另一张，演示继续编辑、放弃或保存并继续，说明笔记归属。
4. 添加来源链接，提交按钮是「添加链接」。打开素材区，说明定位到画板与次级再添加一份的区别。
5. 手动移动一个元素，再加入参考，指出旧位置保持；点整理排版，撤销一次恢复，重做获得同一结果。说明自动整理最多12个元素，手动画板仍可150个。
6. 预览作品、返回，再导出PNG、TXT和JSON。PNG展示作品，TXT保留全文，JSON恢复编辑。自行确认下载位置。
7. 手机按同一链路查看、改笔记、上传、整理和导出；不演示自由拖缩。截图与触屏模拟不能代替实体手机检查。

## 可陈述的事实

- Vue3、TypeScript、Vite和IndexedDB的纯前端视觉参考产品，有两个可编辑示例。
- 第二轮把看图与编辑分开、合并笔记编辑入口、减少常驻三栏，并加入明确触发且一次可撤销的有限整理。
- 新参考找空位，不自动推翻原作品；没有空位保留素材，用户决定是否整理后加入。
- 保留多实例、原位替换、图层、移除、桌面拖缩、历史、手机轻编辑与三类导出；没有存储迁移或新增生产依赖。
- 23项单元测试和本轮UI验收、同源原稿保护、真实导出恢复完成；精确范围和限制以验证记录为准。
- 主要由AI辅助实现和验收，没有独立开发能力、商业用户数或效率提升比例的结论。本轮未推送、部署、修改顾问档案或求职资料。

## 四个短练习

1. 用自己的话说清“放入参考→写想法→排版→导出”的用途与边界。
2. 在 `lib/layout.ts` 找到 `findFreeSpace` 与 `arrangePlacements`，解释为什么加入一张和整板整理是两种操作。

4. 解释为什么未提交笔记要先决定保存/放弃，为什么整理要保持ID和引用，然后亲自撤销、重做和刷新。
