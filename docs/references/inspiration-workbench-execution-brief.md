## 1. 产品目标、信息状态与交付约束

## 3. 必须保留的视觉方向

| 项目 | 必须保留的关系与表现 | 执行者可优化的部分 |
| --- | --- | --- |
| 桌面首屏构图 | 左侧大标题、用途说明及入口；右侧占据显著视觉面积的非对称错落拼贴。图像有大小主次和纵向高低差，形成与文字区的平衡 | 左右比例、文字换行、图像数量和相对位置可调整；不能变成三张等宽图横排、居中标题加整齐卡片墙，或让拼贴缩成小装饰 |
| 排版层级 | 大标题最先被读到，随后是用途说明与主入口；辅助文案退后。保留参考图中中文衬线大字的编辑设计气质 | 选择清楚、许可合适的字体；调整字号、行距和字距。标题可以微调文案，正文和控件用易读字体；不把艺术字体铺满操作区 |
| 色彩 | 暖白基底、炭黑文字、少量朱红强调；图片承载主要色彩变化 | 精确色值、边框、阴影与表面层次可调整；不能整体转暗色，也不能用大面积渐变或发光替代这一方向 |
| 素材表现 | 摄影、版式参考和色彩样张相互衬托；有清楚的光影、质感、冷暖与疏密差异。局部叠放、轻微倾斜、薄边或柔和阴影建立拼贴层次 | 可替换成有使用权且同样有表现力的素材，不必复制同一把椅子、同一张海景或“永”字；避免低清图、重复占位图和满屏同尺寸卡片 |
| 留白与细节 | 标题区有呼吸空间；拼贴密集但能辨认主要图像；装饰不遮挡阅读和点击 | 可减弱纸张纹理、手写点缀和小装饰，调整叠放量；不能为了留白把画面主次削平 |
| 页面延续 | 首屏之后自然展示产品的编排结果与示例，让用户愿意继续看 | 下方编辑器预览的尺寸、位置和衔接可优化，不要求整张概念图的上下比例逐像素复刻，也不增加无关宣传页面 |
| 编辑器 | 浅色、画板居中占主导；顶部功能条、可收起的左侧素材栏，选中后按需出现工具 | 控件密度、浮动工具位置、面板宽度可优化；概念图右侧常驻属性栏不是要求，不照抄其调色、图层、形状或文字工具 |
| 手机 | 保留暖白、标题层级和错落拼贴的辨识度；用途与入口可读可点 | 没有已确认的手机参考图，执行者自行重排为适合窄屏的上下关系，简化次要叠放，不机械缩小桌面页面 |

概念图只指导视觉。色卡、排版样张可作为图片素材展示，不意味着增加配色分析、字体编辑或绘图功能。首页装饰卡片可以倾斜；首版编辑器不提供自由旋转。

## 4. 有边界的设计自主权

在已确认的产品目标、功能、预算和核心视觉方向内，执行者可以主动提出并直接采用能明显提升质量的优化，包括：

- 改善排版比例、素材选择与呈现、留白、信息层级、对比度及响应式布局；
- 优化选中、落点、对齐、保存、导出等反馈；
- 用适度动效帮助理解状态和空间关系，减少突兀跳变。

普通、可逆、不会改变已确认选择的优化，无需逐项询问。简短记录“发现什么问题、如何调整、实际页面验证了什么”即可。不能仅凭偏好宣称更好。

需要用户决定的变化：改变明确选定的核心构图或亮色方向、增加功能或费用、明显延长交付时间。先说明具体收益、代价及范围内可行方案，再交由用户决定；同时可继续不受影响的工作。

不把更多特效、页面或复杂度当成质量提升。动效数量没有固定上限指标，依据注意力、响应速度和舒适度判断。重点打磨：

- 首页零散参考编排成方案的过程；入口从一开始就能操作。
- 素材详情展开/关闭时的位置连贯，关闭后回到原素材。
- 桌面拖动跟手、落点和对齐清楚，松手后稳定。
- 编辑转预览时控件退场，返回时恢复原编辑上下文。

以实际运行效果决定时长、缓动和层次；不得编造“参考要求的精确参数”。避免滚动劫持、遮挡和持续争夺注意力的循环动画；支持减少动态效果，手机不能依赖悬停。粒子、鼠标拖尾、光束继续延后。

## 5. 首版功能与用户可感知行为

### 5.1 首页、示例与草稿

- 主上手方式是“体验示例”，同时有“新建空白方案”；已有本机草稿时提供“继续上次编辑”。
- 两个示例共用编辑器：独立产品网站灵感板，以及摄影与生活方式灵感板。前者展示网页参考和借鉴点，后者展示图片与拼贴表现力。
- 素材数量由构图需要决定，旧版建议的 5～7 张不是验收数量。示例内容要具体、有来源，不用无意义占位文字。
- 点击使用示例生成可编辑副本，原始示例不受影响。
- 新建、切换示例或导入不得静默覆盖已有内容。可以维护一份当前草稿，通过备份提示和明确替换确认保护数据；不因此增加项目管理系统。

### 5.2 素材添加与详情

- 点击选择图片或在桌面拖入；名称、来源和借鉴点可以稍后补充。读取成功后显示缩略图，失败说明原因并允许重试。
- 添加参考链接时手动填网址与标题，可附截图；无截图时显示链接卡片。粘贴网址不触发抓取或第三方预览请求。
- 桌面可点击加入画板或拖入指定位置；点开素材可查看大图和完整说明，关闭后回原位置。
- 来源链接由用户主动点击后打开；限制危险链接协议，备注按文本处理。
- “从画板移除”和“删除素材数据”必须有清楚含义。常规画板删除不应意外清空素材栏或其他引用；破坏性清理不属于新增必做功能。

### 5.3 桌面编辑

- 顶部显示方案名称、保存状态、撤销/重做、预览和导出；左侧素材栏可收起。
- 选中素材后出现替换、编辑说明、前移/后移和删除等操作。
- 自由拖动、角点等比缩放，提供基础对齐辅助线，可做轻量吸附；层叠顺序可调整。
- 原位替换保留位置、外框和层叠关系；新图完整容纳，不拉伸、不隐式裁剪。提醒检查旧来源和借鉴点，未经用户修改不伪造新来源。
- 标题与说明采用统一样式，画板呈现简短借鉴点，详情和清单保留完整文本；长内容不得把卡片撑坏。
- 核心编辑操作支持撤销/重做，包括移动、缩放、替换、删除、叠放和文字修改。一次连续拖动作为一次操作，撤销历史不要求跨刷新保存。
- 预览隐藏工具、选中框与辅助线；退出后恢复编辑上下文。
- 固定画板尺寸由执行者根据示例构图与导出清晰度确定并统一。旧版 1600×1000 只是建议，不是已确认参数；不增加用户尺寸选择器。显示缩放不改变画板坐标或输出布局。

### 5.4 手机轻量操作

- 首页重排；示例、完整画板、大图和说明可访问。画板全貌用于看构图，点击素材后可读完整内容。
- 支持相册上传、添加链接、替换、修改说明、删除、撤销/重做。
- 素材栏与工具改为按需展开的底部面板，保留选中上下文；避免面板、键盘或悬浮按钮遮住正在编辑的内容。
- 沿用示例布局，新素材先进入素材栏；自由拖拽、角点缩放和复杂手势不进入手机首版，也不显示不可用的手柄。
- 手机支持自动保存、PNG 导出、备份与恢复。需要精细编排时提示在电脑完成，跨设备通过备份转移。

## 6. 保存、导出、异常与隐私

自动保存：

- 图片、布局、说明保存在当前浏览器；显示“保存中／已保存到本机／保存失败”，成功提示对应真实写入完成。
- 刷新和重开能恢复。首次简短说明无跨设备同步，清理浏览器数据可能丢失，可导出备份。
- 存储失败不能无声丢弃当前编辑；保留可重试或导出备份的路径。

导出作品：

- 明显入口导出固定尺寸 PNG，保留构图、标题和简短借鉴点，无水印和编辑控件。
- 可同时下载普通文本参考清单，包含方案标题、素材名称、来源网址和完整借鉴点；未填写来源不编造。
- 图片和字体就绪后导出，有处理中及失败反馈，失败不损坏草稿。手机与桌面同一方案使用相同输出尺寸和布局。
- 无 PDF、多档清晰度、复杂设置或云分享链接。

备份恢复：

- 更多菜单提供备份与导入；文件包含图片数据、布局、说明和格式版本，不只记录临时图片地址或原电脑文件路径。
- 导入先验证；损坏、缺图或不支持的版本有明确反馈，保留原草稿。换浏览器导入后应能继续编辑并导出。

异常与数据边界：

- 覆盖本任务相关的空状态、读图失败、格式不支持、文件过大、存储不足和导出失败。具体格式与大小限制由执行者合理确定并告知；PNG/JPEG/WebP 是建议支持范围。
- 用户图片、方案和说明不主动上传服务器或模型。无账号、云同步、统计埋点或会话录制。
- 示例和字体优先本地随站点提供；检查实际网络请求后准确说明隐私，不声称绝对零网络通信。
- 浏览器本机保存与备份是可靠性要求，具体存储库和文件封装由执行者选择。

## 7. 实现空间与素材准备

用户曾表达可加入 Vue 前端的偏好，可优先考虑 Vue；当前记录没有将 Vue/Node、某组件库、禁止 React 或固定目录结构确认为排他条件。旧 Skill 的默认规定不自动变成用户要求，也不需要为解除这些默认规定重开一轮选型讨论。

当前功能适合纯前端静态应用，不需要新增后端或在线数据库。执行者提出简短、可维护且符合预算的实现方案后，在已获开发授权的范围内推进。框架、依赖、代码风格、组件拆分、动效实现与导出方案由实际兼容性和效果决定；改变成本、可行性或关键效果的选择再讨论。

工程建议：图片存储可用 IndexedDB，避免把大量图片塞入 localStorage；将坐标与屏幕缩放解耦；不要把临时对象 URL 当持久化地址。这些是帮助满足可靠性要求的方案，不是附加产品功能。

字体、图片和组件须有适合展示及分发的使用权限，记录来源；可自制素材。参考图不代表生产素材已经取得许可，也不要截取整张概念图伪装成功能界面。执行者自行选取合适资源，只有确实缺少关键材料才向用户说明具体需求，不把搜集大量组件当作用户前置任务。

## 8. 执行与实际页面验收

实施顺序可按技术风险调整，但必须尽早跑通一个完整闭环，再打磨其余已定内容：

1. 读取参考图，形成首页及编辑器的运行页面，检查视觉方向。
2. 示例副本 → 替换 → 桌面编排 → 保存 → 刷新恢复 → 导出。

4. 按以下证据验收并修正明显偏差，再整理交付。

### 8.1 视觉与动效必须对照实际页面

在宽桌面、常见笔记本、窄手机和较宽手机视口查看；具体尺寸由执行者记录，必要时补查布局临界宽度。不能只看一张大屏截图。

将实际首页截图与第一轮 A 并排对照，并用简短记录检查：

- 桌面是否仍是左大标题、右侧有视觉分量的错落拼贴？是否误做成等宽横排或普通卡片墙？
- 标题、用途说明、主入口的顺序是否明确？图片尺寸差异、叠放、留白和色彩是否共同形成层次？
- 暖白/炭黑/少量朱红的关系是否保留？摄影与版式素材是否清楚、有质感、有差异？
- 编辑器是否以画板为主，控件能读能点，选中反馈清楚，长说明不破坏排版？
- 手机是否在重排后保留辨识度，标题和入口可见，拼贴没有遮挡或溢出，底部面板和文字可用？

手机按同一方向和可用性验收，不宣称存在已确认的手机参考稿。概念图中的额外工具和精确像素不作为相似度目标。

交互与动效需实际操作或短录屏验证：拖动跟手、松手稳定；详情开关不丢位置；预览退出可继续编辑；动画不阻塞按钮、不产生明显闪跳；减少动态效果模式可完成操作。静态截图不能证明这些项目通过。

发现明显偏差后，在授权范围内自行修正，并复查受影响的页面和操作；若修正必须改变已确认构图、增功能/费用或明显延长交付，再说明收益和代价。不得把偏差简单标为“个人审美不同”后交付。无需在无变化、无新增风险时反复全面检查。

### 8.2 功能、数据与工程证据

- 两个示例可编辑且原稿不变；上传横图/竖图、无截图链接、替换和说明可连贯完成。
- 桌面移动、等比缩放、叠放、删除与撤销正确；不同显示比例下不发生拖动位置偏移。
- 编辑后刷新恢复；在独立浏览器环境导入备份后图片、文字和布局完整；无效备份不覆盖原草稿。
- 验证保存失败与导出失败反馈；失败不伪报成功、不损坏草稿。
- 同一方案在手机和桌面的 PNG 输出尺寸与布局一致；图片、字体、说明不缺失，文本清单准确。
- 手机实际完成查看、上传、替换、编辑说明、保存、导出与恢复。若只使用浏览器模拟，明确标记；未经真机测试不能声称全机型通过。
- 执行生产构建及所选技术适用的类型/静态检查；对保存恢复、备份校验、坐标和撤销做与风险相称的验证或测试。记录命令与结果，不要求无意义测试数量，也不编造性能成绩。
- 核查网络请求符合本机处理边界；具体存储限制和已知兼容性问题写入交付说明。

## 9. 完成标准、交付物与后续边界

投递前必须完成：

- 本文所列首版主流程、桌面编辑、手机轻量体验、保存导出及备份可用。
- 实际页面对照参考方向完成检查，明显构图、可读性、交互和动效偏差已修正。
- 可运行源码与启动说明、中文 README、素材来源、少量实际运行截图、操作验证结果及已知限制。
- 简短视觉复核记录：参考方向、实际表现、改动及验证依据；必要时附关键交互短录屏。
- 一份简短演示步骤及事实清单，服务求职讲解。简历可在作品推进时同步整理。

整体成果完成后，把讲解拆成少量短节：产品解决什么问题及为何收紧范围；一个关键交互如何实现；本机保存与备份的区别；一个实际遇到并修复的问题。让用户能操作和复述，再扩展知识，不要求先学完整框架课程。

区分“已实现”“已验证”“本人已理解”。AI 完成的代码不能自动写成用户独立掌握的能力；简历只写真实贡献和可演示结果，不虚构工作年限、客户、指标或开发职责。

投递后再按需要考虑：PDF、更多导出设置、更多示例、独立收藏库与筛选、手机精细编排、粒子/拖尾/光束。这些是候选，不是自动排入计划的需求。

明确不进入首版：账号、云同步、协作、社区、订阅、无限画布、脑图、自由富文本、绘图、复杂图层、自由旋转、裁剪及专业图片编辑、AI 功能、网页抓取、浏览器插件、自动配色分析、双主题。

阶段结束简短记录已完成、已验证、未完成及下一步，便于中断后恢复。仅在用户明确要求发布时选择符合零新增付费条件的托管方案并核查实际限制。达成首版标准后转向演示、理解和投递，不继续以增加页面或特效延后交付。
